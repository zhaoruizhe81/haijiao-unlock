# haijiao-unlock

海角社区的付费视频解锁用户脚本。

> **一句话原理:站点把"付没付费"的判断放在了接口层,而没有放在资源层。**
> 脚本不去骗接口,只是把它本来就够得着的那份播放列表换成完整版。

本文只讲**思路**。可运行的实现看 [`haijiao-unlock.user.js`](./haijiao-unlock.user.js)。

---

## 一、先看清楚:付费墙建在哪一层

拿到一个"付费才能看"的页面,第一件事不是找绕过,而是**定位这道墙砌在哪**。常见的三种位置:

| 位置 | 表现 | 可解性 |
|---|---|---|
| **资源层** | CDN 只存了试看文件,完整文件根本没上传 | 无解 |
| **接口层** | 资源都在 CDN 上,只是接口对未付费用户**故意下发另一份地址** | **可解** |
| **解密层** | 资源下发完整,但密钥只发给付费用户 | 取决于密钥是否也被同一层管控 |

这个站是**第二种**:试看和完整版是同一个 CDN 目录下的**两个不同文件**,两份都对外可读,接口只是告诉播放器该拉哪一个。判断方法和结论:

1. 试看列表能匿名拉到 → 资源层没做鉴权
2. 试看文件里的分片能正常播放 → 播放链路完整可用
3. 那么只要知道"完整版叫什么名字",就能直接拉

**这一步是整个工作的分水岭。** 如果第 1、2 步就 403,后面所有努力都是白费,应该直接掉头去查解密层。

## 二、从最小样本里找"稳定标识"

试看列表本身只有几十秒,但它**不是随机生成的**——它是从完整版里截出来的。这意味着:

- 试看分片的命名、密钥、IV 都可能与完整版**共享**
- 分片名里往往嵌着母资源的标识

实测发现试看列表的每个分片名里都带一个**稳定的前缀**,这个前缀就是母流的 ID。拿到它,完整版的文件名就是可枚举的——一个很短的候选集。

> 反过来,当分片名是**纯随机串**(不可枚举、无公共前缀)时,这条路直接断掉。见第六节。

## 三、用 HEAD 探测,别用 GET

候选文件名不多,但**不要用 GET 去试**:

- GET 会把整个文件下回来,浪费带宽、拖慢页面、还容易触发风控
- `HEAD` 只拿响应头和 `Content-Length`,干净、快、可并发

脚本对每个候选做一次 `HEAD`,第一个命中的就是完整列表。**判定依据不只是状态码**——有些 CDN 对不存在的路径返回 200 + 一个很小的错误体,所以要同时看 `Content-Length` 是否合理。

> 实测补一句:`Content-Length` 也可能**根本没有**(分块传输)。所以"状态码 200 但长度是 null"不等于失败,判据得是"200 且不是那种一望而知的小错误体",而不是简单地要求长度大于某个数。

拿到完整列表后,可以顺手对比段数与时长确认无误(试看 17 段 / 30s vs 完整一百多段 / 两分钟出头,差异非常明显)。

## 四、只改"入口",不改"数据"

定下思路后,实现上有一个重要的取舍:**在哪里动刀?**

| 方案 | 评价 |
|---|---|
| 改接口返回,把 `is_buy` 之类字段伪造成已购 | ❌ 改数据,牵扯面大,任何一处校验都会崩 |
| 前端重渲染,直接把付费内容塞进 DOM | ❌ 伪造已成事实的状态,和站点的状态机打架 |
| **只把播放器要加载的 URL 换掉** | ✅ 只改一个入口点 |

脚本选第三种:**在播放器把列表喂给解码器之前,把 URL 换掉**。除了这一个赋值,页面其他部分完全不知道发生了什么——购买状态、按钮、DOM 都是原样。

同理,试看列表里带的那个**密钥混淆文件**,完整版那份可能不存在。因为两份列表共享同一条母流,密钥材料是同一套,所以可以让完整版的那次请求**回落**到试看那份。这里同样只想一件事:让播放链路跑通。

## 五、下载:把一堆分片拼成一个能离线播的文件

解锁让页面**能看**,下载要的是**能带走**。这是两条不同的链路。

### 5.1 分片是加密的,但工具是现成的

列表里带一条 key 声明:加密方式 AES-128,**IV 也明写在列表里**。每个分片是独立的 AES-128-CBC + PKCS#7——所以解出来的明文正好比密文短一个填充块。

浏览器自带的 WebCrypto 就能做这件事,**不需要任何第三方库**。

### 5.2 密钥不是直给的(全部难点在这里)

密钥文件拿回来是 16 字节,但**直接拿它去解是解不开的**——站点在密钥上又套了一层变换:把密钥字节和另一个"混淆文件"的字节一起喂给自己 wasm 里的某个函数,输出才是真密钥。

这里不能靠猜变换逻辑。脚本做的是**复用站点自己的那次变换**:调它自己已经加载好的那个 wasm 模块,喂同样的输入,拿同样的输出。所以**哪怕站点以后改了变换算法,只要它自己还能播,这条路径就跟着能用**。

> ⚠️ 顺带一个安全提醒:那个"混淆文件"的内容看着像一条数据库连接串。**它是饵。**
> 站点往 CDN 上放的假凭据,专门钓那些翻 CDN 的人——真去连就是自投罗网。
> 脚本只把它当作变换的**输入字节**,从不解析它的内容,更不会去连。

### 5.3 拿到密钥先别急着下:验一遍

密钥对不对,**不需要下完整个视频才知道**。做一次自验证:

拿第一个分片解一下,明文开头必须是 MPEG-TS 的同步字(`0x47`,而且之后每 188 字节一次)。对不上就换下一个候选混淆文件;全试完还对不上,**直接报错**。

**宁可不下载,也不产出一个"看着像视频"的坏文件。** 一个 20 MB 的坏文件比一句明确的报错糟糕得多——用户会以为是播放器的问题,然后花半小时排查。

### 5.4 并发抓,但按顺序写

瓶颈是分片数量(一条两分钟的视频一百多个分片),所以要并发。但**拼装必须按顺序**。做法是:

- **同时开 N 个请求**,N 可配
- **谁先完成谁等着**,严格按分片顺序往文件里写

这样内存占用只跟**并发数**有关,跟视频多长**无关**。否则一个四十分钟的视频不是下载,是内存炸弹。

支持的话优先用浏览器原生的文件写入(先拿句柄,再边下边写);不支持就退回"内存拼好再存"。

> **文件句柄必须在最开始就要。** 浏览器的"保存文件"对话框依赖**用户手势**,而中间只要 `await` 过一次,手势就过期了——那时再调会直接失败。所以流程是"先问存哪,再开始干活",不是"干完活再问存哪"。

### 5.5 产出是什么

两个按钮,对应两种产出:

- **MP4(默认)** —— 把 TS 重新封装成分片式 MP4。H.264 + AAC 原样搬过去,`ffprobe` 能正确读出视频轨/音频轨/时长,主流播放器直接能播。
- **TS(原始)** —— 不重封装的原始产物。零依赖、最快、体积略大(TS 每 188 字节要带 4 字节包头,而且还有 PAT/PMT 这类表)。列表本来就是 fMP4 的话,这个按钮给到的也是 mp4。

**两条路都不转码。** 转码是另一个量级的复杂度(得拖进一个几 MB 的 wasm 版 ffmpeg),又慢又掉画质。

### 5.6 要 MP4,就别说"我自己写一个 muxer"

TS → MP4 的重封装不是"换个后缀"——要从 TS 里解出 PES、还原出 H.264 的访问单元、再按时间戳拼出 `moov`/`moof`/`mdat` 那一套盒子。自己写是几百行起步,而且错一点点就产出打不开的文件,还很难 debug。

所以这里**直接用成熟的 `mux.js`**(Apache-2.0,被 video.js / hls.js 生态长期验证的那个)。它在 hls.js 里本来就在干同一件事,只是没对外暴露,所以用脚本元数据里的 `@require` 把它引进来。

取舍写得明白:

- 它是**一次性下载、缓存在 Tampermonkey 里**的,不是页面运行时去拉的;
- 只有当你真的点 MP4 那个按钮时才会用到它;
- 万一它没加载上(CDN 被挡、装的是旧版本脚本),脚本会**明确告诉你并降级到 TS**,而不是产出一个坏文件。

**结论:能复用被验证过的工具,就不要自己写一个只有你测过的版本。** 这条在第七节会再出现一次。

## 六、诚实记录:这条路走不通的那一半

**新格式的帖子解不了。** 站点改版后,试看分片名变成了 32 位随机十六进制:

- 没有公共前缀 → 提取不出母资源标识
- 不可枚举 → 候选集是 2^128

试过很多方向都没用:枚举文件名、换路径、换域名、猜 hash 原像。结论很干脆——**当"试看"不再是母资源的切片,而是**独立生成**的一段新视频时,CDN 上根本不存在"完整版文件"这个东西**,资源层这道墙才是真的砌上了。

脚本遇到这种帖子会**明确报告"不支持"**,而不是静默失败或假装成功。下载功能在这种情况下会给到的是**试看那份**,文件名里也会标出来。

## 七、通用方法论

换一个站点,复用这套流程:

1. **分层**:先用最少的请求搞清楚墙砌在资源层、接口层还是解密层。**这一步定生死。**
2. **找泄漏**:试看/预览/缩略资源往往是母资源的切片,切片里通常残留母资源的标识。
3. **探测**:候选集用 `HEAD` 枚举,同时校验状态码和响应特征,别信单一信号。
4. **最小改动**:只改"让播放器拿到正确地址"这一个入口。改数据必然牵扯状态机。
5. **复用而不是复刻**:密钥变换、解密这类逻辑,优先**调目标自己的实现**而不是逆出来重写——它改了你也不用跟。
6. **验证产出**:对"能解出来"这件事要有一个**结构性判据**(比如 TS 的 188 字节同步字),而不是"没报错就算成功"。
7. **验证边界**:确认自己到底拿到了什么、没拿到什么,并且**把不支持的情况明确报出来**。

## 八、踩过的坑

### 8.1 摘掉了弹窗,整页还是点不动(v1.0.2 修复)

站点的公告弹窗是 Element-UI 的 Dialog。最初的清理逻辑把弹窗的 DOM 直接 `remove()` 掉,看起来干净——然后**整个页面被一层灰雾盖住,什么都点不了**。

原因:`.v-modal` 这个遮罩不是弹窗的**子元素**,而是全局**唯一**的共享遮罩,由组件的 `PopupManager` 用模态栈管理。直接删 DOM,框架的栈并不会出栈,遮罩就永久留在页面上(半透明黑 + `pointer-events: auto` = 整页瘫掉),同时 `body` 上还挂着滚动锁。

**教训:用 DOM 手术绕过框架组件时,框架的内部状态不会跟着你走。** 要么走它自己的关闭 API,要么就得连它留下的**副作用**一起收拾。

修法也要小心:判断"遮罩是不是孤儿"不能看"还剩几个弹窗容器"——站内自己就有常驻的隐藏容器,那个条件永远不成立。**唯一可靠的判据是"有没有真正渲染出来的弹窗"**(容器 `display` 不为 `none` 且内部弹窗有非零尺寸)。同时要等一拍再动手,因为真弹窗进场动画的头几帧尺寸还是 0,立即处理会误杀它的背景。

### 8.2 别信 `JSON.stringify` 的"看起来一样"

调试时遇到过:两个对象 `JSON.stringify` 出来**一个字都不差**,但一个合法一个非法。差别在于其中一个对象里有个**值为 `undefined` 的键**——`JSON.stringify` 会把它**静默删掉**,而严格的边界校验查的是"这个键是否存在"。

**序列化后的字符串相同 ≠ 两个对象相同。** 排查这类问题时,要看对象本身,别拿字符串化结果当证据。

### 8.3 浏览器的"用户手势"会被 `await` 吃掉

`showSaveFilePicker()` 这类 API 要求**瞬时用户激活**。但它不是"这个会话里点过按钮就行",而是一个**几秒钟的窗口**——中间只要 `await` 过一个网络请求,窗口就关了,再调直接抛错。

直觉上很自然会写成"先把活儿干完,最后问用户存哪",而这**必然失败**。正确的顺序是反过来:**先问存哪,再干活**。

推论:凡是"需要用户手势"的调用,都要放在事件处理函数里**最靠前**的位置,前面不能有任何异步。

### 8.4 CDN 上可能有专门给逆向者准备的饵

翻资源的时候,某个路径返回的内容**看起来像一条带账号密码的数据库连接串**。

乍看像"捡到宝",实际上**这正是它被放在那里的原因**——一个只有翻 CDN 的人才会看到的路径,返回一个只有翻 CDN 的人才会当真的字符串。连上去就等于自己报上名了。

**判断依据**:一个正常业务不会把自己的凭据放在一个公开可读的静态文件里。凡是"顺路捡到的凭据",先默认它是**投毒**,再去找证据推翻这个默认。

### 8.5 隐藏元素的 `textContent` 照样能读到

下载下来的文件被命名成了 `你正在移动1个帖子到请选择.mp4`——**内容完全正常**(ffprobe 认、全量解码零错误),只有名字是垃圾。

名字来自一个"同步猜标题"的函数,它按 `h1 → .post-title → .title → [class*="title"]` 依次找,取第一个文本非空的。两个问题叠在一起:

1. 页面上**第一个 `h1` 的文本是空的**(它只是个图标容器),于是被跳过;
2. 落到 `.title` 时,命中的是站点的**「移动帖子」弹窗**——一个隐藏的对话框。

**关键点:`textContent` 和"屏幕上的文字"完全是两回事。** 隐藏元素里的文本照样能读到:

```
{"cls":"title","text":"你正在移动1个帖子到请选择","display":"block","rect":"0,0 0x0"}
                ↑ 文字读得到                              ↑ 但它根本没渲染出来
```

所以"用 `querySelector` 取到元素、文本非空"**完全不能**作为"这是页面上可见的标题"的依据。修法是加一道**渲染检查**:逐级往上确认所有祖先都不是 `display:none` / `visibility:hidden` / `opacity:0`,元素自己有非零尺寸。再加上一份 UI 文案黑名单(`请选择`、`正在移动`、`我的置顶`、`举报`……)兜底。

**通用教训:凡是"从 DOM 里读点什么当数据用",先问一句"这东西真的在屏幕上吗"。** 隐藏的弹窗、模板、预渲染节点全都在 DOM 里,而且它们的文本和你想要的文本长得一模一样。

## 九、安装

1. 装 [Tampermonkey](https://www.tampermonkey.net/)
2. 点开 [`haijiao-unlock.user.js`](./haijiao-unlock.user.js),Tampermonkey 会弹出安装页;或直接把 `.user.js` 拖进浏览器

## 十、配置

脚本顶部 `CFG` 里的开关:

| 键 | 默认 | 说明 |
|---|---|---|
| `unlock` | `true` | 解锁完整播放列表(核心功能) |
| `preferPreviewKeyBlob` | `true` | 密钥混淆文件优先回落试看那份(同流同密钥,最稳) |
| `hideAds` | `true` | 隐藏广告位 |
| `killNotices` | `true` | 清掉站点公告弹窗并解除整页遮罩/滚动锁 |
| `blockAdRequests` | `false` | 直接掐掉广告位请求(更干净,但某些皮肤会剩空盒子) |
| `showButtons` | `true` | 显示角标 + 复制链接 / 本页播放按钮 |
| `download` | `true` | 显示两个下载按钮(MP4 重封装 / TS 原始) |
| `downloadConcurrency` | `6` | 下载并发分片数(按序处理,内存占用与视频长度无关) |
| `debug` | `true` | 控制台日志 |
| `maxSegments` | `0` | >0 时只保留前 N 段(调试用) |

## 十一、这个脚本不做什么

这条边界是**有意画的**:

- **不修改**任何接口返回,不伪造 `is_buy` / `sale` 之类的购买状态
- **不上传、不回传**任何数据;访问站点的请求一律不带 `credentials`;不向任何分析/统计服务发东西
- 唯一的第三方来源是 **`mux.js`**(重封装器),由 Tampermonkey 通过 `@require` **一次性拉取并缓存**,不是页面在运行时去请求的。除此之外没有任何外部依赖
- **不改 cookie**、不碰账号态
- **不解服务端的任何校验**——服务端从头到尾没参与

关于解密要说清楚,因为它分两条路径:

- **播放路径**:不碰加密链路,解密完全由站点自己的播放器流程完成,脚本只负责把地址换对。
- **下载路径**:确实会在本地解密——用**站点自己的** wasm 做密钥变换,再用浏览器 WebCrypto 解分片。但这不是"绕过"什么:密钥本来就随播放列表发给了所有人,只是包了一层变换而已。脚本只是在本地把它解开,好让你得到一个能离线播的文件。

## 十二、已知限制

- **新版帖子解不了**(见第六节),脚本会明确报告而不是假装成功;下载功能在这种情况下给到的是试看那份
- 下载器**不支持 `EXT-X-BYTERANGE`** 的列表,遇到会明确报错而不是产出坏文件
- 站点改动 CDN 命名规则或密钥变换方式即会失效;本脚本是**一个时间点的观察结果**,不是长期保证
- 只在前述几个域名下生效
