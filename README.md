# haijiao-unlock

海角社区的付费视频解锁用户脚本。

> **一句话原理:站点把"付没付费"的判断放在了接口层,而没有放在资源层。**
> 脚本不去骗接口,只是把它本来就够得着的那份播放列表换成完整版。

本文只讲**思路**。可运行的实现看 [`haijiao-unlock.user.js`](./haijiao-unlock.user.js)。

---

## 一、先看清楚:付费墙建在哪一层

拿到一个"付费才能看"的页面,第一件事不是找绕过,而是**定位这道墙砌在哪**。常见的三种位置:

| 位置 | 表现 | 可解性 |
|---|---|---|
| **资源层** | CDN 只存了试看文件,完整文件根本没上传 | 无解 |
| **接口层** | 资源都在 CDN 上,只是接口对未付费用户**故意下发另一份地址** | **可解** |
| **解密层** | 资源下发完整,但密钥只发给付费用户 | 取决于密钥是否也被同一层管控 |

这个站是**第二种**:试看和完整版是同一个 CDN 目录下的**两个不同文件**,两份都对外可读,接口只是告诉播放器该拉哪一个。判断方法和结论:

1. 试看列表能匿名拉到 → 资源层没做鉴权
2. 试看文件里的分片能正常播放 → 播放链路完整可用
3. 那么只要知道"完整版叫什么名字",就能直接拉

**这一步是整个工作的分水岭。** 如果第 1、2 步就 403,后面所有努力都是白费,应该直接掉头去查解密层。

## 二、从最小样本里找"稳定标识"

试看列表本身只有几十秒,但它**不是随机生成的**——它是从完整版里截出来的。这意味着:

- 试看分片的命名、密钥、IV 都可能与完整版**共享**
- 分片名里往往嵌着母资源的标识

实测发现试看列表的每个分片名里都带一个**稳定的前缀**,这个前缀就是母流的 ID。拿到它,完整版的文件名就是可枚举的——一个很短的候选集。

> 反过来,当分片名是**纯随机串**(不可枚举、无公共前缀)时,这条路直接断掉。见第五节。

## 三、用 HEAD 探测,别用 GET

候选文件名不多,但**不要用 GET 去试**:

- GET 会把整个文件下回来,浪费带宽、拖慢页面、还容易触发风控
- `HEAD` 只拿响应头和 `Content-Length`,干净、快、可并发

脚本对每个候选做一次 `HEAD`,第一个命中的就是完整列表。**判定依据不只是状态码**——有些 CDN 对不存在的路径返回 200 + 一个很小的错误体,所以要同时看 `Content-Length` 是否合理。

拿到完整列表后,可以顺手对比段数与时长确认无误(试看 17 段 / 30s vs 完整一百多段 / 两分钟出头,差异非常明显)。

## 四、只改"入口",不改"数据"

定下思路后,实现上有一个重要的取舍:**在哪里动刀?**

| 方案 | 评价 |
|---|---|
| 改接口返回,把 `is_buy` 之类字段伪造成已购 | ❌ 改数据,牵扯面大,任何一处校验都会崩 |
| 前端重渲染,直接把付费内容塞进 DOM | ❌ 伪造已成事实的状态,和站点的状态机打架 |
| **只把播放器要加载的 URL 换掉** | ✅ 只改一个入口点 |

脚本选第三种:**在播放器把列表喂给解码器之前,把 URL 换掉**。除了这一个赋值,页面其他部分完全不知道发生了什么——购买状态、按钮、DOM 都是原样。

同理,试看列表里带的那个**密钥混淆文件**,完整版那份可能不存在。因为两份列表共享同一条母流,密钥材料是同一套,所以可以让完整版的那次请求**回落**到试看那份。这里同样只想一件事:让播放链路跑通,不去碰解密本身。

## 五、诚实记录:这条路走不通的那一半

**新格式的帖子解不了。** 站点改版后,试看分片名变成了 32 位随机十六进制:

- 没有公共前缀 → 提取不出母资源标识
- 不可枚举 → 候选集是 2^128

试过很多方向都没用:枚举文件名、换路径、换域名、猜 hash 原像。结论很干脆——**当"试看"不再是母资源的切片,而是**独立生成**的一段新视频时,CDN 上根本不存在"完整版文件"这个东西**,资源层这道墙才是真的砌上了。

脚本遇到这种帖子会**明确报告"不支持"**,而不是静默失败或假装成功。

## 六、通用方法论

换一个站点,复用这套流程:

1. **分层**:先用最少的请求搞清楚墙砌在资源层、接口层还是解密层。**这一步定生死。**
2. **找泄漏**:试看/预览/缩略资源往往是母资源的切片,切片里通常残留母资源的标识。
3. **探测**:候选集用 `HEAD` 枚举,同时校验状态码和长度,别信单一信号。
4. **最小改动**:只改"让播放器拿到正确地址"这一个入口。改数据必然牵扯状态机。
5. **验证边界**:确认自己到底拿到了什么、没拿到什么,并且**把不支持的情况明确报出来**。

## 七、踩过的坑

### 7.1 摘掉了弹窗,整页还是点不动(v1.0.2 修复)

站点的公告弹窗是 Element-UI 的 Dialog。最初的清理逻辑把弹窗的 DOM 直接 `remove()` 掉,看起来干净——然后**整个页面被一层灰雾盖住,什么都点不了**。

原因:`.v-modal` 这个遮罩不是弹窗的**子元素**,而是全局**唯一**的共享遮罩,由组件的 `PopupManager` 用模态栈管理。直接删 DOM,框架的栈并不会出栈,遮罩就永久留在页面上(半透明黑 + `pointer-events: auto` = 整页瘫掉),同时 `body` 上还挂着滚动锁。

**教训:用 DOM 手术绕过框架组件时,框架的内部状态不会跟着你走。** 要么走它自己的关闭 API,要么就得连它留下的**副作用**一起收拾。

修法也要小心:判断"遮罩是不是孤儿"不能看"还剩几个弹窗容器"——站内自己就有常驻的隐藏容器,那个条件永远不成立。**唯一可靠的判据是"有没有真正渲染出来的弹窗"**(容器 `display` 不为 `none` 且内部弹窗有非零尺寸)。同时要等一拍再动手,因为真弹窗进场动画的头几帧尺寸还是 0,立即处理会误杀它的背景。

### 7.2 别信 `JSON.stringify` 的"看起来一样"

调试时遇到过:两个对象 `JSON.stringify` 出来**一个字都不差**,但一个合法一个非法。差别在于其中一个对象里有个**值为 `undefined` 的键**——`JSON.stringify` 会把它**静默删掉**,而严格的边界校验查的是"这个键是否存在"。

**序列化后的字符串相同 ≠ 两个对象相同。** 排查这类问题时,要看对象本身,别拿字符串化结果当证据。

## 八、安装

1. 装 [Tampermonkey](https://www.tampermonkey.net/)
2. 点开 [`haijiao-unlock.user.js`](./haijiao-unlock.user.js),Tampermonkey 会弹出安装页;或直接把 `.user.js` 拖进浏览器

## 九、配置

脚本顶部 `CFG` 里的开关:

| 键 | 默认 | 说明 |
|---|---|---|
| `unlock` | `true` | 解锁完整播放列表(核心功能) |
| `preferPreviewKeyBlob` | `true` | 密钥混淆文件优先回落试看那份(同流同密钥,最稳) |
| `hideAds` | `true` | 隐藏广告位 |
| `killNotices` | `true` | 清掉站点公告弹窗并解除整页遮罩/滚动锁 |
| `blockAdRequests` | `false` | 直接掐掉广告位请求(更干净,但某些皮肤会剩空盒子) |
| `showButtons` | `true` | 显示角标 + 复制链接 / 本页播放按钮 |
| `debug` | `true` | 控制台日志 |
| `maxSegments` | `0` | >0 时只保留前 N 段(调试用) |

## 十、这个脚本不做什么

这条边界是**有意画的**,不是能力所限:

- **不修改**任何接口返回,不伪造 `is_buy` / `sale` 之类的购买状态
- **不上传、不回传**任何数据;不发任何第三方请求;不带 `credentials`
- **不绕过加密本身**——解密仍由站点自己的密钥流程完成,脚本只负责让播放器拿到正确的列表
- **不改 cookie**、不碰账号态

## 十一、已知限制

- **新版帖子解不了**(见第五节),脚本会明确报告而不是假装成功
- 站点改动 CDN 命名规则即会失效;本脚本是**一个时间点的观察结果**,不是长期保证
- 只在前述几个域名下生效
